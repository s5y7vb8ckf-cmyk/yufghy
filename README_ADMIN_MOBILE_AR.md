# MILO CASHIER — لوحة إدارة الجوال

## ماذا تحتوي النسخة؟

- `admin.html` صفحة مستقلة باللغة العربية تعمل على الجوال أو التابلت أو الكمبيوتر.
- `admin.css` تصميم لوحة إدارة رسمي ومتجاوب.
- `admin.js` ربط اللوحة بالخادم وإدارة الواجهات.
- `AdminBackend.gs` وظائف الإدارة المنفصلة في Google Apps Script.
- `Code.gs` نفس خادم MILO السابق، مع **سطر توجيه واحد فقط** قبل عمليات الحساب المعتادة حتى يستقبل `admin*`.
- باقي ملفات الكاشير والموقع والفواتير ضمن النسخة ولم تتغير في هذا التحديث.

## التركيب (مرة واحدة)

1. احتفظ بنسخة احتياطية من ملف Google Sheets وكود Apps Script والموقع المنشور قبل البدء.
2. افتح مشروع Google Apps Script **المربوط بقاعدة بيانات الكاشير الحالية**.
3. استبدل محتوى ملف `Code.gs` الحالي بمحتوى الملف الجديد الموجود في هذه الحزمة.
4. في محرر Apps Script اضغط **+ > Script** وأنشئ ملفًا جديدًا باسم `AdminBackend`، ثم الصق فيه محتوى `AdminBackend.gs` بالكامل. لا تُلصقه بدل Code.gs. يقرأ هذا الملف نفس أوراق قاعدة البيانات دون مسح أي سجلات.
5. من **Project Settings > Script Properties** أضف الخصائص الثلاث التالية:
   - `MILO_ADMIN_SETUP_STORE`: قيمة `store_code` الخاصة بمتجرك في ورقة `Accounts`.
   - `MILO_ADMIN_SETUP_USER`: اسم مستخدم مستقل لمدير المتجر (3-80 محرفًا إنجليزيًا/رقميًا).
   - `MILO_ADMIN_SETUP_PASSWORD`: كلمة مرور قوية مكوّنة من 12 حرفًا على الأقل.
6. شغّل الدالة `miloAdminSetupFromProperties` من محرر Apps Script واسمح لها بالأذونات اللازمة. تتحقق من وجود المتجر وتجهّز الحساب، ثم **تحذف خاصية كلمة المرور المؤقتة** من Script Properties. لا تحذف خصائص المتجر واسم المستخدم بعد الإعداد إلا إذا أردت تنظيف الإعدادات.
7. حدّث نشر تطبيق الويب: **Deploy > Manage deployments > Edit > New version > Deploy**. يجب أن يبقى النشر مربوطًا بجدول البيانات الصحيح. لا تستخدم إصدارًا قديمًا لا يحتوي `AdminBackend`.
8. انشر ملفات الموقع (بما فيها `admin.html` و`admin.js` و`admin.css`) على استضافتك الحالية المخصصة للكاشير. عند اكتمال النشر، رابط الإدارة هو:
   `https://YOUR-SITE-DOMAIN/admin.html`
9. افتح الرابط من الجوال أو الكمبيوتر. أدخل كود المتجر، ثم اسم المستخدم وكلمة المرور الإدارية اللذين أعددتهما في الخطوة 5.

## ما الذي يمكن إدارته؟

- لوحة إحصاءات المبيعات والضريبة والنقد والشبكة والفواتير، مع فترة قابلة للاختيار ومخطط مبيعات.
- إضافة المنتجات وتعديل الأسعار والمخزون والتصنيفات والصور، دون إعادة تسجيل المبيعات.
- عرض طلبات الزبائن وتحديث الحالات **غير المكتملة**. إكمال الطلب وتحصيله وإصدار فاتورته يبقى من الكاشير حفاظًا على سلامة الورديات والفواتير.
- عرض الورديات، وإضافة وتعديل العملاء والموردين والموظفين والمصروفات والمشتريات والعروض والمرتجعات والسندات.
- إعدادات المتجر العامة وتغيير كلمة مرور الإدارة.

## تنبيهات مهمة

- **لا تضع كلمة مرور المدير أو مدير النظام داخل JavaScript أو رابط الموقع.** يتم التحقق منها في Apps Script؛ الجلسة مؤقتة ولا تُحفظ في المتصفح.
- بيانات الدخول الإدارية **مستقلة عن بيانات دخول الكاشير**. إنشاء موظف في قسم الموظفين هنا لا ينشئ حساب تسجيل دخول جديدًا تلقائيًا؛ القسم سجل إداري ولا يقدم إدارة صلاحيات متعددة حتى الآن.
- الحساب الإداري الواحد له صلاحية تعديل بيانات متجر واحد. لا يوجد اعتماد دفع، حذف شامل، أو تغيير فواتير مسجلة من هذه اللوحة.
- إضافة منتج بباركود محذوف سابقًا قد يرفضها الخادم لمنع رجوع منتج محذوف بسبب مزامنة قديمة.
- ربط شاشة الجوال يتطلب اتصال الإنترنت ووجود صلاحيات نشر Google Apps Script الصحيحة واستخدام HTTPS لاستضافة الموقع.
- **لا تجرّب على بيانات مبيعات حقيقية مباشرة.** جرب أولًا إدخال صنف تجريبي من الإدارة، تأكد من ظهوره بالكاشير، جرّب تقرير الفترة، ثم راجع سجل الفواتير والطباعة.
- هذا التحديث لا يغير أي ملف طباعة أو واجهة نقطة البيع؛ ولكنه يضيف إجراءات إدارية إلى قاعدة البيانات. لا يمكن ضمان التشغيل الكامل دون اختبار فعلي مع حسابك ونسخة النشر.

## تفاصيل الأمان

- كلمة مرور الإدارة لا تُخزن نصًا صريحًا في خصائص الخادم بعد الإعداد. يخزن السكربت بصمة مجزأة مع ملح منفصل.
- الجلسة صالحة نظريًا حتى ست ساعات أو حتى إخلاء ذاكرة الخادم المؤقتة.
- محاولات تسجيل الدخول الخاطئة محددة، وتغيير كلمة المرور يبطل الجلسات السابقة.
- *محدودية أمنية مهمة*: Google Sheets + Apps Script حل خفيف وليس نظام صلاحيات مؤسسيًا متقدمًا. كما أن نظام الكاشير الأصلي يستخدم طريقة دخول منفصلة ينبغي تقويتها قبل استخدام الإنتاج واسع النطاق.
